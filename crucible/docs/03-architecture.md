# 代码与目录架构

> 这份写项目现在的结构。运行时规则与数据契约见 `04-foundations.md`，改动过程见 `../../docs/crucible/README.md`。

## 1. 一条总则

代码是给 AI 看的，也是给人看的，但最终是给人看的。目录和命名按人会怎么找东西来切，不按技术框架来切。

判断只有一条：没读过代码的人，能不能靠目录树和文件名猜出东西在哪。猜得出就合格。

## 2. 顶层目录

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `docs/` | 项目现在的事实：玩法、美术、结构 | 代码、临时文件 |
| `data/` | 物质、装置的数据表 | 任何逻辑 |
| `src/` | 代码 | 数据表、美术资源 |
| `assets/` | 材质、精灵、界面、音频 | 手改的生成物 |
| `tests/` | 测试，镜像 `src/` 结构 | 测试数据，放 `fixtures/` |
| `web/` | itch 入口与构建产物 | 手写源码 |

## 3. src 的分层

| 目录 | 负责 | 可引用 | 不可引用 |
|---|---|---|---|
| `app/` | 装配、主循环、设置、存档 | 全部 | — |
| `world/` | 网格、温度、反应、步进 | `data/`、`events.ts` | 装置、渲染、界面 |
| `devices/` | 装置的读写行为与注册表 | `world/`、`data/`、`events.ts` | 渲染、界面 |
| `render/` | 只读状态画画面 | `world/`、`devices/`、`events.ts` | 写世界状态，界面 |
| `ui/` | 面板、悬停、图鉴、工具栏 | `world/`、`devices/`、`events.ts` | 写世界状态，渲染 |
| `events.ts` | 事件名与载荷类型，唯一跨层文件 | 无 | 全部 |

依赖单向，上表可引用列之外一律不许 import。三条硬约束：

1. `render/` 与 `ui/` 只读世界状态，不写。
2. 输入只产生命令，命令由 `app/` 派发，界面不直接改世界。
3. 世界不反向依赖装置。装置的作用是把读写网格的动作挂进步进，由 `app/` 编排顺序。

## 4. 数据与代码分开

`data/` 只有 JSON，不 import 任何代码。加一种物质、一种装置，原则上只加数据。

启动时按 schema 校验，报错要指到文件和字段。

## 5. 命名

- 目录与文件用 kebab-case。
- 文件名回答「它负责什么」，不回答「它是什么类型」。
- 不设 `utils`、`helpers`、`common`、`misc`、`core`、`lib`、`types`。跨层共用的只有 `events.ts`。
- 同一个概念全仓只用一个词：物质 material，装置 device，信号 signal。

## 6. 规模上限

- 文件不超过 300 行，函数不超过 60 行。
- 目录层级不超过 3 层，不含 `src/` 与 `data/`。
- 同一目录不超过 15 个文件。超了按人怎么找再分，不按字母分。

## 7. 加东西的样子

加一种物质叫酸。如果它的反应类型已经存在，只改两处：

1. `data/materials/acid.json` 写属性与反应。
2. `assets/tiles/acid.png` 放贴图。

需要新的反应类型时，才动 `src/world/reactions.ts` 加一条规则。

加一种装置叫冷凝器：

1. `data/devices/condenser.json` 写参数。
2. `src/devices/condenser.ts` 写读写行为。
3. `src/devices/registry.ts` 注册一行。

只动这两处。registry 是注册表，不是 barrel 索引，不允许重导出全部模块。

## 8. 为什么这对 AI 也好

结构清晰、名字达意、纯函数多的代码，人和 AI 一样好改。真正让 AI 出错的是隐藏耦合：跨目录的隐式状态、同名不同义、循环依赖。这些同时是人最难读的。

所以不需要为 AI 单独设一套规范。把「人能读懂」做到位，AI 自然好改。

## 9. 验收

1. 只看目录树，能说出每个顶层目录和 `src/` 子目录负责什么。
2. 只读 `src/world/` 一个目录，能完成「加一条反应规则」。
3. 加一种物质不改 `src/`；加一种装置只改一个实现文件加注册一行。
4. 没有 `render/` 或 `ui/` 写世界状态；没有 `world/` 引用 `render/`。
