# 公共文档布局

## 背景

这个仓库原来只放通用规则，设计文档放在 `docs/superpowers/specs/`，只有一份。现在仓库里有了专题项目，项目的问题排查、重构方案、功能方案也需要一个固定的地方。之前没有类型、状态和索引，文档容易和项目自己的说明混在一起。

## 决策

1. `docs/` 只放“一次改动怎么发生、为什么这么选”；项目现在的事实留在项目自己的文档目录。
2. 先按项目分：项目文档放 `docs/<项目>/`；仓库级文档直接放 `docs/` 根目录。
3. 文档分四类：决策记录、排查记录、方案、评审记录（可选）。
4. 根目录的文件名加类型前缀；项目里按类型分目录。根目录同一类超过 5 份再建子目录。
5. 状态写在文档开头的元信息里；索引放 README；不建 `archive/`。
6. 变更文档可以写日期和状态；`.dsh/`、`templates/` 和根目录的规则文档仍然不写日期、作者、版本和修改过程。

## 备选

| 方案 | 做法 | 为什么不选 |
|---|---|---|
| 全部放各项目文档目录 | 变更文档跟项目走 | 跨项目的决定没有地方放，只能塞进某个项目 |
| 全部按类型放 | 根目录建 `plans/`、`issues/` 等，项目作为下一层 | 项目文档被拆散，`docs/<项目>/` 不再完整 |
| 保留旧目录 | 继续用 `docs/superpowers/specs/` | 没有状态和索引，容易和新做法并存，最后对不上 |

## 后果

- 要维护两个索引：`docs/README.md` 和 `docs/<项目>/README.md`，由 `scripts/check-docs.sh` 检查。
- 原来的设计文档迁到 `docs/PLAN-2026-11-12-generic-rules-library.md`，根 README 和 AGENTS 里的链接同步更新。
- 新增 `.dsh/conventions/change-docs.md`，把“什么时候写、写哪一种、写成什么样”变成可以复用的约定。
- 只有需要先写方案的改动才写，小改动不额外造文档。
