# 移除委托与操作员

## 背景

- 要解决的问题：demo 已经能玩，但「委托」和「操作员」这两套系统占了大量代码、数据和文档，却说不清它们贡献了什么玩法。
- 观察：委托的玩法是「画一笔达成目标」——笔刷一次能盖住门槛的十几倍，四个委托都靠一两下点击通关；操作员则是「在两个点之间搬格子」，玩家没有任何可优化的决策。
- 关键判断：这两套东西都不产生「看懂规律 → 设计装置 → 自动运转」的乐趣，反而让玩家以为游戏是「涂色过关」。

## 决策

1. 删除 `src/contracts/`、`src/crew/`、`src/ui/contracts.ts` 与 `data/contracts/`。
2. 删除「取料点」「卸料点」两种装置，装置从 8 种减到 6 种。
3. 删除 `spawn-operator` 命令、`Operator` 状态、快照里的操作员表、`contract.*` 事件。
4. 只剩「自由沙盘」：玩家自己定目标，用物质与装置搭链子。
5. 依赖方向检查同步收窄为 `main/app/world/devices/render/ui` 六层。

## 备选

| 方案 | 做法 | 为什么不选 |
|---|---|---|
| 保留委托、改强约束 | 委托里禁用编辑、要求用装置达成 | 要做的其实是「关卡设计」，工作量远大于收益，且和沙盘的自由感冲突 |
| 保留操作员、只删委托 | 让人当唯一的活物 | 操作员没有决策空间，玩家只会觉得它挡路 |
| 全部保留、下一版再删 | 先做别的功能 | 每加一个功能都要同时兼容两套东西，越拖越贵 |

## 后果

- 代码少了两层、17 个文件（原本 21 个）；测试从 89 个降到 76 个，删掉的是委托与操作员专用用例。
- 游戏没有「关卡」了，新手引导只能靠开场说明页和沙盘本身。要不要补「目标提示」是下一版的事。
- `08-physics-review.md` 里与委托、操作员相关的条目只剩历史价值，文首已注明。
- 以后要加回类似「目标」的东西，新写 ADR，不要复活 `contracts/` 与 `crew/`。
