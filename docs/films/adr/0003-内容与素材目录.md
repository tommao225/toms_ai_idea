# 内容与素材目录

## 背景

现在文本和图片放在少数几个目录里。榜单和电影一多，找东西、替换素材、删一部片都会互相影响。一部电影可能同时属于两个榜单，素材不能按榜单复制两份。

## 决策

「板块」定义为一个榜单（list_id），「电影」定义为 movie_id。两者交叉的内容放板块下，电影自己的内容放电影下，同一份素材只存一次。

```text
data/
├─ curated/
│  ├─ lists/<list_id>/
│  │  ├─ list.toml        # 榜单定义、口径、卷名
│  │  └─ entries.csv      # 名次、movie_id、这一榜的手记
│  └─ movies/<movie_id>/
│     ├─ quote.md         # 台词或摘句，带出处
│     └─ note.md          # 跨榜通用说明（可选）
├─ media/
│  ├─ lists/<list_id>/
│  │  ├─ hero.webp        # 板块头图
│  │  └─ chapter-01.webp  # 卷封面（可选）
│  └─ movies/<movie_id>/
│     ├─ poster.webp
│     ├─ still-01.webp
│     ├─ still-02.webp
│     └─ credits.json     # 来源、授权、作者、是否占位
├─ raw/tmdb/<movie_id>.json
├─ movies/movies.jsonl
├─ lists/<list_id>.json
└─ awards/awards.jsonl
```

- 板块专属的文本（名次、这一榜的手记）放板块目录；电影的公共素材（海报、剧照、台词）放电影目录。
- 同一张图、同一句台词只存一份；板块页通过 movie_id 引用。
- 构建产物（`movies.jsonl`、`lists/*.json`、`awards.jsonl`）保持按文件输出，不按板块或电影拆，避免同一份数据出现多次。
- 占位图也放电影目录，和真实剧照同路径，用 `credits.json` 标 `placeholder`。

## 备选

| 方案 | 做法 | 为什么不选 |
|---|---|---|
| 全平铺 | 所有图片放一个目录 | 片子一多就找不到，删除和替换容易误伤 |
| 按榜单复制 | 每个榜单存一份海报和剧照 | 同一张图存多份，改一处漏一处 |
| 按类型或年代分 | 按悬疑、科幻、动作或年代分 | 一部片跨类型时会重复，按电影反而更难找 |

## 后果

- 要更新 `data/README.md`、`01 实现路径`、`pipeline/README.md` 和 `.gitignore` 里的路径。
- 管线要按 `movie_id` 找素材；板块页按 `list_id` 找头图和条目。
- 目录比以前深，但每个文件只属于一个板块或一部电影，删除和替换不会牵连别的。
