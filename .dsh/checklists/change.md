# 提交前自检

> 逐项打勾；不适用的项写明理由，不要直接跳过。验证面怎么选见 `../conventions/verification.md`，完成判定见 `../rules/completion-verification.md`。

## 范围

- [ ] 改动只覆盖本次任务声明的范围，没有顺手重构无关文件
- [ ] 撞见的无关缺陷已登记，没有在本批直接修改
- [ ] 重构与行为修改分开提交，或在提交说明里分开描述
- [ ] 每个被改文件都能说清为什么属于本次范围

## 复用与边界

- [ ] 新增前已搜索现有实现，没有造第二套同类能力（输入、选择器、弹层、数据加载、格式化等）
- [ ] 新逻辑优先调用现有共享函数与领域函数，没有再抄一份
- [ ] 纯逻辑层没有新增 DOM、网络请求、全局对象依赖
- [ ] 页面层之间没有新增互相引用
- [ ] 新增导出都有实际调用点；删除的导出没有遗留引用

## 原子化

- [ ] 每个文件职责单一，没有继续膨胀超长文件
- [ ] 函数长度与嵌套层级在项目约定上限内，超了已拆
- [ ] 没有为单个调用点抽象出框架
- [ ] 状态放在最小作用域；模块级状态有唯一入口与清理路径
- [ ] 命名与既有风格一致，没有引入同义不同名的概念

## 数据

- [ ] 没有覆盖或删除用户已有内容
- [ ] 空值、缺失值、非法值有显式处理，没有被当成合法值
- [ ] 新字段具备「写入 → 校验 → 读取 → 展示」完整链路
- [ ] 数据文件按项目约定的格式化方式重排后无意外差异
- [ ] 数据文件引用的外部资源已同批提交
- [ ] `git status` 里没有遗漏未跟踪的新模块、资源、配置

## UI

- [ ] 没有新增绕过统一组件的原生控件或第二套交互
- [ ] 颜色、圆角、间距、层级优先使用既有 token
- [ ] 空态、错误态、加载态、窄视口至少各看过一次
- [ ] 弹层、抽屉、浮层的滚动锁、焦点、关闭清理正常
- [ ] 删除组件时其样式、标记、选择器引用同批清理

## 验证

- [ ] 语法/类型检查覆盖所有改动文件
- [ ] 受影响的页面或命令实际执行过，不只是读代码
- [ ] 写入链路验证过：保存 → 重新读取 → 展示一致（改了数据或表单时）
- [ ] 常驻进程已重启并用真实请求验证（改了服务端时）
- [ ] 生成类资源重新生成后无差异（改了派生资源时）
- [ ] 汇报写清验证了什么、没验证什么

## 文档

- [ ] 需要先写方案的改动已经写了方案，P0、P1 都有结论，状态和检查结果已更新（见 `../conventions/change-docs.md`）
- [ ] 文档写给人看：术语第一次出现时有解释，没有空话、套话和重复内容
- [ ] 改动文档和项目现有文档没有写重复的内容
- [ ] 新增、移动、删除的文档已在所属索引里同批更新
- [ ] 文档里的路径、入口名、字段、限制与实际一致
- [ ] 注释只写「为什么」，没有日期、版本、变更叙事
- [ ] 相关规则/约定需要更新的已同批更新
- [ ] 新增或删除的入口在索引类文档里已同步

## 通用化（仅当本次产出要跨项目复用时）

机检只能抓禁用词，抓不到「换成别的项目就读不懂」的残留，靠这四项人工判：

- [ ] 例子没有退化成某个具体项目的形态：特有组件名、真实目录结构、某条业务规则
- [ ] 判据去掉项目名后仍可执行，不依赖读者了解某个项目
- [ ] 命令保留形状、去掉事实：路径与端口都是占位
- [ ] 术语在库内只出现一种叫法，跨文件一致
