# 子 Agent 使用手册

> 子 agent 是并行工具，不是流程必需品。范围小、单文件改动、需要连续决策的工作由主 agent 直接做；只有「范围大、彼此独立、主上下文会被淹没」时才派。派之前先读 `../rules/agent-discipline.md`。

## 1. 什么时候派

| 场景 | 派不派 |
|---|---|
| 全仓找同类问题（死代码、重复实现、风格不一致） | 派，按方向拆成多个只读 agent |
| 多文件、多维度的审查 | 派，一个 agent 一个维度 |
| 单文件小改 | 不派 |
| 需要主上下文连续决策的重构 | 主 agent 做，子 agent 只做独立审计 |
| 安全、数据正确性、权限相关核查 | 派只读 agent，主 agent 复核结论 |
| 需要独立验证实现（verifier），避免自证 | 派只读复核 agent |

## 2. 角色边界

- **审计 agent**：只读。不改文件、不执行写操作、不启动或停止服务；输出「位置 + 证据 + 建议」。
- **实现 agent**：只改分配到的文件范围；不碰他人负责的文件；完成后报告改了哪些文件、跑了哪些验证命令、结果如何。
- **复核 agent**：只读改动差异与运行结果，找回归与遗漏；不把审计 agent 的结论当事实，也不复用实现 agent 的自评。
- 同一文件同一时间只允许一个写者；需要并行时按目录或文件拆分写域，写域之间不得重叠。
- 子 agent 不得提交、推送、切分支、删文件；需要这些动作时交回主 agent。

## 3. Prompt 必须包含

1. 工作目录，以及只读/可写权限与可写范围
2. 任务范围：查什么、改什么，具体目录与文件类型，明确不做什么
3. 禁止项：不改文件、不 git 写、不启动或停止服务（只读审计时）
4. 输出格式：按优先级分组，每条给位置、问题、证据、建议
5. 要求区分「确认」与「推断」，不确定的明确标出
6. 要求报告方法：读了什么、搜了什么、跑了什么命令及输出
7. 要求最后给出按优先级排序的「建议先做」清单

## 4. 主 Agent 的职责

- 装配题面，不预先把结论塞给审计 agent（避免只剩核对）。
- 收集结果后**抽查可实测断言**：
  - 「某文件多少行」→ 实际计数
  - 「某函数零调用」→ 全仓搜索
  - 「保存后格式会变」→ 实际重启服务并发起真实请求
  - 「某处没有样式」→ 搜索样式表
  - 「某路径不存在」→ 直接访问或列目录
- 合并去重，剔除误报，标注哪些已核验、哪些仍是推断。
- 多个子 agent 结论冲突时，以可复现的实测结果为准。
- 合并前自己看最终差异，并跑一遍全量验证。

## 5. 经验条目

- **结论必须回到运行态验证。** 源码看起来对，不代表正在运行的进程已加载；报告与源码一致也可能是旧进程或旧构建。验证方式是重启后真实请求或真实交互。
- **并发结论冲突以实测为准。** 多个 agent 指向同一现象时，重合不等于正确；用一次可复现的实验裁决，把实验输出作为证据。
- **删除类操作需人确认。** 子 agent 只能列出「建议删除」清单与影响面，不能自动执行删除；不可逆删除由人确认后再动。
- **并行审计只发面，不当修复清单。** 并行 agent 擅长发现「哪里有问题」，不擅长排修复依赖；修复顺序由主 agent 按依赖与风险重排。

## 6. 输出模板

```markdown
## 高
1. `<位置>` — 问题一句话
   - 证据：读了什么 / 搜了什么 / 实测输出
   - 建议：具体改法
   - 置信度：确认 / 推断

## 中
...

## 低
...

## 已排除（避免误报）
- ...

## 建议先做
1. ...
```
