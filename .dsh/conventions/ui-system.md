# UI 约定：组件、token、交互一致性

## 1. 一个交互只有一个实现

界面层的纪律不是「写得好看」，而是**同一个交互全站只有一个实现**。用户能感知的重复（两套下拉、两种抽屉、两种关闭方式）都是缺陷。

判断口径：新增交互时先找现成组件；找不到才扩展组件库，而不是在页面里现写一份。

## 2. 复用优先

已有统一组件，不得另起一套：

| 需求 | 统一组件 | 该组件负责 |
|---|---|---|
| 下拉、可搜索选择、单选/多选 | 统一下拉 | 触发器与原生控件值同步、过滤、键盘导航、同一时间只开一个 |
| 日期/时间（年→月→日，可限制粒度） | 统一日期控件 | 三级导航、粒度约束（只到月/必须到日）、清空语义 |
| 层级数据选择（多级分类、树形归属） | 统一级联控件 | 默认项与默认层级、搜索只作用于末级、返回上级、可输入过滤 |
| 右侧编辑面板 | 统一抽屉 | 滚动锁、冻结操作区、关闭回调、未保存草稿回滚 |
| 多图查看（键盘、遮罩、索引） | 统一灯箱 | 索引切换、Esc/遮罩关闭、滚动锁恢复、点击不误触底层 |
| 文件选择/预览/移除 | 统一上传字段 | 预览、移除只更新记录不删底层文件、失败提示、数量上限提示 |
| 面板折叠与最大行数 | 统一折叠面板 | 互斥展开、行数上限、内部滚动 |
| 父/子同构表单 | 统一表单 | 子级字段与父级同构、前置校验、草稿状态 |
| 列表统计/明细渲染 | 统一列表渲染器 | 转义、空行占位、非法态标注 |

用法要点：

- 动态生成的行/卡片重建后，重新初始化统一组件；程序化改值后同步显示，不靠下次交互兜底。
- 需要新增变体时改组件本身（加参数），不复制组件再改。
- 组件替换后旧实现必须删除，不能留着「以防万一」。

## 3. 禁止清单

- **禁止第二个下拉**：不得新增可见的原生 `select` 或另写一套自定义下拉。
- **禁止第二个日期控件**：不得直接暴露浏览器原生日期输入作为可见控件。
- **禁止第二套灯箱、抽屉、遮罩**：包括在页面里临时拼一层半透明层。
- **禁止复制组件 HTML 再改**：复制一份再调颜色/文案，等于制造第二个实现。
- **禁止页面直接拼数据请求**：URL、查询参数、鉴权头、错误处理统一走数据访问层，页面只调用语义化方法。
- 禁止用无键盘支持的 `div` 当按钮。
- 禁止用 `!important` 覆盖主题 token；先修 token 或选择器。
- 禁止在脚本里硬编码主题色；需要运行时取值就读计算后的样式。

## 4. 设计 token

**优先级从高到低**：

1. 复用已有 token；
2. 扩展现有 token（在唯一 token 文件里定义一次）；
3. 组件内私有变量（作用域限定，仅该组件使用）；
4. 页面内硬编码——禁止。

颜色、圆角、阴影、间距、层级都用 token；`z-index` 必须走层级 token，禁止随手写 9999。

新增 token：

1. 先全仓搜是否已有近义 token；
2. 在唯一 token 文件定义一次，命名说清用途而非色值；
3. 替换至少两个已有使用点，证明它真是共性；
4. 不把 token 值复制成脚本常量；需要就给计算后的值；
5. 改 token 后在浅色底上检查文字与焦点环对比度。

判据：全仓搜十六进制色值与 `rgba(`，新增硬编码命中为 0（或集中在 token 文件内）。

## 5. 交互一致性

所有浮层（下拉、日期、抽屉、灯箱、提示条）共用同一套行为：

- **单开**：同一时间只允许一个浮层；嵌套打开时 Esc 只关最上层，逐层关闭。
- **滚动锁**：打开时锁页面滚动，关闭恢复打开前的值；嵌套用计数，不能硬置空或直接复位成默认值。
- **焦点归还**：关闭后焦点回到触发元素；触发元素已不存在则落到其所在容器，不丢到 `body`。
- **键盘**：Enter/Space 触发；上下键与 Home/End 移动；Esc 关闭；Tab 不落进背景内容。
- **定位**：挂到不被 `overflow` 裁切的位置（浮层容器），且不超出视口；滚动容器内打开要跟随或关闭。
- **幂等**：重复打开/关闭不累积监听器、不残留浮层。

判据：每个浮层逐项手测「键盘 → Esc → 滚动锁 → 焦点归还 → 再开一次」。

## 6. 状态

- **空态**：说清为什么空、下一步做什么；全站一个空态样式，不新增类名。
- **错误态**分三档：页面级、区块级、字段级。不新增第四种；错误文案以文本可见，不只靠颜色或边框。
- **保存态**：进行中、成功、失败、离线草稿四种，文案固定；失败要给可执行动作（重试/导出），不显示原始异常。
- **前置校验**：前端先拦明显错误（必填、类型、成对、范围），服务端校验不可省；不允许「保存成功后才发现被拒」。
- 列表加载失败与「确实没有数据」必须可区分，不能都渲染成空态。

## 7. 移动端与响应式

- 至少两个视口实际打开验证：窄屏（≤480）与常规（≥768）；有宽表格或宽浮层再加一档。
- 多列卡片与栅格在窄屏单列；不为塞下列数压字号。
- 吸顶栏不遮内容；浮层层级高于吸顶栏；抽屉在窄屏全宽、表单单列。
- 触控目标足够大且不重叠；横向滚动只用于表格这类必须保持结构的场景。
- 断点值全仓收敛：新增不引入新数值，优先复用已有断点。

## 8. 可访问性底线

- 可点击元素用原生 `button`；非原生元素补 `role`、`tabIndex` 与 Enter/Space。
- 输入有可读 label；触发器维护展开状态与当前项；灯箱的上一张/下一张/关闭有可读名称。
- 打开模态后 Tab 不进入背景内容，或至少保证 Esc 与关闭按钮始终可用。
- 焦点环在浅色背景上可见；换主题色后重新检查对比度。

## 9. 术语统一

同一概念全仓一个词。判据：

1. **用户可见处只有一个写法**：按钮、提示、空态、错误、导出文案、文档一致。
2. **文案与命名各自一致即可**：用户可见文案一套词，代码/数据模型一套命名；不为文案统一去改字段名、文件名、类名。
3. **新增词先搜**：已有词能覆盖就不新增；确实不同义，写清差异再引入。
4. **有意的区分必须说明**：如「移除记录」与「删除数据」语义不同，要在同一处写明，否则统一成一个词。
5. **改名一次改完**：全仓搜近义词，改完再搜一次，确认只剩一个写法。
6. 项目自己的词表放项目仓库；本约定只给判据，不收录具体词。

## 10. 样式与清理

- 一个样式文件一个职责，不混多个页面。
- 新样式先复用现有类；不复制整段再改颜色。
- 删除组件时同步删除其样式；提交前全仓搜旧类名与旧选择器。
- 已超长的文件只许变小；改到它时优先拆出独立职责。

## 11. 自查

- [ ] 新增交互都能指到某个统一组件；指不到说明应扩展组件库。
- [ ] 全仓搜可见原生控件与第二套实现，命中为 0 或有登记例外。
- [ ] 颜色/圆角/阴影/层级无新增硬编码。
- [ ] 每个浮层验证：键盘、Esc、滚动锁恢复、焦点归还、单开。
- [ ] 窄屏实际打开过页面，空态与错误态都看过。
- [ ] 用户可见近义词搜一遍，只剩一个写法。

交互改动的验收矩阵见 `./verification.md`；提交前过一遍 `../checklists/change.md`。
