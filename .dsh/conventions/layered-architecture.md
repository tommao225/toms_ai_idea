# 架构约定：分层、依赖方向、适配层

## 1. 分层

```text
页面层
  │
  ├──> 适配层 ──┐
  │             ├──> 领域层 ──> 通用层
服务层 ─────────┘
离线脚本（独立进程，不参与运行时）
```

| 层 | 一句话定位 |
|---|---|
| 通用层 | 无业务倾向的工具：选择器、转义、日期、数据加载、通用交互组件 |
| 领域层 | 纯模型与计算：校验、归一化、排序、筛选、统计、派生 |
| 适配层 | 外部世界隔离面：第三方库对象、网络、文件系统、渲染目标 |
| 页面层 | 骨架、交互状态、渲染、表单 |
| 服务层 | 独立进程：HTTP、鉴权、校验、读写数据、落盘 |
| 离线脚本 | 数据生成、格式化、迁移等一次性或周期任务 |

依赖方向：箭头指向被依赖方，只允许上层依赖下层。

- 页面层可以依赖适配层、领域层、通用层。
- 领域层只依赖通用层的纯工具，不碰浏览器、网络、文件系统、渲染目标。
- 通用层不依赖任何页面。
- 服务层可复用领域层与通用层，不 import 页面层。
- 离线脚本可复用领域层与通用层，不 import 页面层。

层级不是目录名，而是「谁能依赖谁」的约束；目录与层的映射见 [module-layout](./module-layout.md)。

## 2. 每层职责

| 层 | 应该放 | 不应该放 |
|---|---|---|
| 通用层 | 与业务无关的工具、通用组件、数据加载入口 | 业务字段、页面布局、业务规则 |
| 领域层 | 纯函数：校验、归一化、排序、筛选、统计、派生 | DOM 操作、网络请求、文件读写、第三方渲染对象 |
| 适配层 | 第三方库封装、请求、文件读写、格式转换 | 业务规则、页面布局 |
| 页面层 | 骨架、交互状态、渲染、表单、页面级编排 | 第二份业务计算、服务端校验 |
| 服务层 | HTTP 入口、鉴权、入参校验、原子写入、落盘 | 页面渲染、前端交互逻辑 |
| 离线脚本 | 数据生成、格式化、批量迁移 | 被运行时 import、依赖页面 |

## 3. 适配层

外部世界必须被挡在领域层外：

- 领域层返回普通数据对象（纯值、数组、映射），不返回第三方库类型。
- 领域层不生成任何渲染产物（节点、片段、图标文本）。
- 适配层负责把第三方库对象、网络响应、文件内容转成纯数据，再交给领域层。
- 数据加载只保留一个入口：页面与脚本都通过它取数据，不各自拼路径、各自解析格式。
- 新增外部依赖时先问两句：能否在适配层隔离？领域层是否因此仍能在无浏览器环境里纯测？两个答案都是「能」才引入。

## 4. 数据流

```text
数据文件
  → 唯一加载入口
  → 领域层：校验 + 归一化
  → 领域层：派生（排序 / 筛选 / 统计 / 汇总）
  → 页面层渲染 / 适配层转换
  → 用户操作
  → 表单读取
  → 校验（前端 + 服务端）
  → 原子写入
  → 重新加载验证
```

任何一环都不能跳过校验，也不能静默丢弃字段：读进来不认识的字段要么报错，要么保留并透传，不允许悄悄删掉。

## 5. 加新模块的判定

| 场景 | 放哪 |
|---|---|
| 两个以上页面都要用的纯函数 | 领域层（含业务语义）或通用层（不含） |
| 只服务单个页面的交互 | 页面层 |
| 只服务编辑表单 | 页面层 |
| 服务端校验、存储 | 服务层 |
| 一次性数据生成、格式化 | 离线脚本 |
| 页面骨架、样式 | 页面层；样式按组件拆分 |

不确定时优先放在离调用点最近的层；出现第二个调用点再上移。上移前先确认两处调用语义真的一致，不要为了「复用」抽出一个参数越来越多的函数。

## 6. 纯计算与 UI 的边界

- 纯计算模块只导出函数与常量，不读 DOM、不写存储、不读全局状态。
- 计算入口保持稳定：新增公式先加纯函数与用例，再接 UI。
- 页面层认识业务，但不重新推导公式；同一个算法全仓只有一份实现。
- 所有用户输入先归一化、再校验、最后计算；顺序反了就会出现「先算错再提示」。
- 状态集中在页面入口的单一对象里，字段带默认值；读取时按类型与范围归一化，并兼容旧数据缺失字段。
- 渲染函数只读状态、只写渲染目标，不改业务状态；动态重建的节点要重新初始化其绑定的组件。
- 拆分只做搬移，不改行为；行为变更单独提交。

## 7. 禁止

- 领域层 import 页面层或适配层。
- 通用层 import 任何页面。
- 页面之间互相 import：页面共用的东西下沉到通用层或领域层。
- 服务层 import 页面层模块。
- 用全局变量传递应用状态（第三方库的既定入口除外）。
- 维护「万能工具」文件，把不相关逻辑塞在一起。
- 在页面层写第二份业务计算或第二份校验。

## 8. 评审快查

1. 新增代码属于哪一层？目录与层一致吗？
2. 依赖方向有没有反向？
3. 领域层还能在没有浏览器、没有网络的环境里跑吗？
4. 有没有同一算法的第二份实现？
5. 数据流里有没有环节跳过校验或静默丢字段？
6. 改动后新增文件是否 ≤ 300 行、新增函数是否明显膨胀？

架构判断之外，改动流程见 [../checklists/change.md](../checklists/change.md)，完成标准见 [../rules/completion-verification.md](../rules/completion-verification.md)。
