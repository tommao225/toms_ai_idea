# 验证范围与命令

## 1. 按改动面选验证

| 改了什么 | 必跑 |
|---|---|
| 任意源码文件 | 全量语法检查 + 受影响页面的冒烟 |
| 纯函数 | 语法检查 + 用例（正常值、边界值、非法输入）+ 对应页面行为 |
| 共享组件 | 所有使用它的页面；组件自身的打开、关闭、销毁 |
| 表单 | 打开、填写、保存、刷新后仍在；未保存草稿关闭时回滚；非法输入被拦截 |
| 数据文件或数据结构 | 格式可解析 + 写入链路 + 重新读取 + 消费它的页面 |
| 本地服务 | 语法检查 + 重启进程 + 正常请求 + 安全负向请求 |
| 上传 | 合法文件落盘后可访问；伪造类型、超大、越界路径被拒 |
| 静态资源 | 页面里实际出现；请求返回 2xx；引用路径与生成结果一致 |
| 样式与页面骨架 | 真实浏览器渲染；空态、窄屏、滚动与吸顶、弹层 |
| 删除与重构 | 全仓搜旧名 0 命中 + 相关页面回归 + 用例全绿 |
| 文档与规则 | 引用路径存在、命令可执行、描述与代码事实一致 |

选验证时按「改动实际影响面」取行，不要只取最省事的一行。

## 2. 基础命令模板

下列命令是形状，路径按目标项目替换；`<源码目录>`、`<数据文件>`、`<入口文件>` 都是占位。

```bash
# 源码语法（JS 类）
for f in $(find <源码目录> -name '*.js'); do node --check "$f" || exit 1; done

# 源码语法（Python 类）
python3 -m py_compile $(find <源码目录> -name '*.py')

# 数据文件可解析、结构可读
python3 - <<'PY'
import json
from pathlib import Path
data = json.loads(Path('<数据文件>').read_text())
assert isinstance(data, (dict, list))
print('parsed', len(data))
PY

# 单测 / 项目自带检查
<项目测试命令>

# 旧名残留（删除或重构后必须 0 命中）
grep -rn "<旧名>" <源码目录> || echo clean

# 生成产物可复现（有生成脚本时）
<生成命令> --check
git diff --exit-code <生成产物路径>
```

命令跑不通时先修环境或命令本身，不要用「没跑」代替「通过」。

## 3. 页面冒烟

至少确认：

- 默认入口能加载，无未捕获错误。
- 列表与详情：有数据时渲染条数正确，无数据时出现空态而不是空白或报错。
- 编辑入口：打开、填写、保存、刷新后仍在。
- 窄屏宽度：无横向溢出，弹层不超出视口。
- 涉及弹层时：打开、切换、点遮罩关闭、Esc 关闭、关闭后滚动恢复。

数值类页面还要核对一个已知输入的期望输出，不只看「有没有渲染出东西」。

## 4. 本地服务安全负向请求

思路是：正常请求要通，越权与越界请求要拒。路径与端口按项目替换，凭据从环境或启动输出取。

```bash
# 正常路径：必须 2xx
curl -s -o /dev/null -w "%{http_code}\n" "<基地址>/"
curl -s -o /dev/null -w "%{http_code}\n" -H "<凭据头>: <凭据>" "<基地址>/<读接口>"

# 敏感路径：必须 403 / 404
curl -s -o /dev/null -w "%{http_code}\n" "<基地址>/<敏感路径>"

# 写接口：无凭据必须 401 / 403
curl -s -o /dev/null -w "%{http_code}\n" -X POST "<基地址>/<写接口>"

# 跨站来源：必须 403
curl -s -o /dev/null -w "%{http_code}\n" -H "<凭据头>: <凭据>" -H "Origin: <外部来源>" "<基地址>/<写接口>"

# 错误内容类型：必须 400 / 415
curl -s -o /dev/null -w "%{http_code}\n" -X POST -H "<凭据头>: <凭据>" \
  -H "Content-Type: text/plain" --data '{}' "<基地址>/<写接口>"
```

`<敏感路径>` 至少覆盖：版本库元数据、服务端源码、日志与备份、上级目录穿越。负向请求返回 2xx 就是漏洞，不是「能用」。

## 5. 验证边界

- 只跑了语法，不能说「页面正常」。
- 只跑了局部页面，不能说「全量回归通过」。
- 只检查源码，不能说「运行态已生效」；服务端改动必须重启后再验。
- 只截一张图，不能说交互与持久化通过。
- 子 agent 的结论要抽查可实测项，不能当事实直接引用。
- 没跑的项目在汇报里明确写「未验证」，不要含糊成「应该没问题」。

## 6. 证据格式

汇报验证时给出四段：

1. 命令 / 页面 / 视口。
2. 实际结果：数量、状态码、读取到的文本或数值、截图路径。
3. 失败项与原因。
4. 未覆盖范围。

示例（中性）：

```text
- 纯函数：用例 12/12 通过；空输入返回空集合，不返回 0
- 页面：默认入口渲染 8 条记录；窄屏 480px 无横向滚动；空态文案出现
- 服务：重启后正常请求 200；<敏感路径>=404；无凭据=401；跨站来源=403
- 未覆盖：上传超大文件未测（缺少测试样本）
```

验证通过只是完成标准的一部分，另外三层见 [../rules/completion-verification.md](../rules/completion-verification.md)；静默失败的自查见 [../rules/silent-failure.md](../rules/silent-failure.md)。
