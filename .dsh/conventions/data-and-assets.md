# 数据与资源约定

## 1. 单一事实源

- 一条数据只有一个权威写入点（一个文件、一张表或一个接口），其余都是读取或派生。
- 派生文件（索引、骨架、缩略图、聚合结果）必须由脚本从权威源生成，禁止手改；生成物要能看出「由什么生成」。
- 同一事实不得在多处各写一份；确实需要副本时，指定唯一写入方向，并给出一致性检查命令。
- 数据格式（字段、层级、编码）以权威源为准；文档与示例从它摘，不能反向编一份再让数据迁就文档。

判据：随便挑一个字段，能说出唯一写入点；全仓搜字段名，除派生与读取处外没有第二处写。

## 2. 字段消费链

新增字段必须四环齐全，缺一环就不许加：

1. **写入**：编辑表单、接口入参或导入脚本给值处；
2. **校验**：前端关键校验 + 服务端强制校验，规则写清（必填、类型、范围、枚举、成对）；
3. **读取**：数据访问层读取并做缺省处理；
4. **展示**：渲染处分别处理缺失与非法；无展示的字段必须写明仅内部计算。

规则：

- 删除字段同样倒查四环；只删写入不删展示等于留死代码。
- 未知字段在保存时必须原样保留，不能因编辑器没渲染就丢弃。
- 保存后重新读取一次再判断成功；内存里的对象不等于已落盘。
- 字段默认值只写在一处，不在表单、接口、读取层各写一份不同的默认。

判据：删掉任一环，能指出用户会看到什么异常（能填不能显示 / 前端能存服务端拒收 / 空值变 0）。

## 3. 空值语义

- 空串、`null`、缺失、`0`、空数组、空对象，各自含义必须写清；不同语义不得共用一种表示。
- **`0` 不等于空**；格式化、排序、统计不得把空当 0、把 0 当空。
- **成对字段**必须成对存在或成对为空：范围起止、上下界、最小/最大、原文/译文。只出现一半视为非法，校验层直接拒绝。
- 可选字段为空时统一表示（例如统一用空串），不混用 `null` 与缺失。
- 派生字段（标签、摘要、统计值）由主字段算出；主字段变更必须重算或清理旧值。
- 不保存可由主字段推导、又从不独立编辑的值；确实要存就明确标为缓存并说明失效规则。

判据：构造一条「全空」和一条「全 0」数据，页面与统计结果必须不同且都合理。

## 4. 格式化器唯一 + `--check`

- 每种数据格式只有一个格式化入口（一个命令或一个函数）；不允许第二个脚本再实现一套排版。
- 格式化器必须幂等：连续跑两次无 diff。
- `--check` 只报告不修改，退出码非 0 表示需要重排；用于提交前与校验脚本。
- 新增格式需求扩展原格式化器，不改数据去迁就工具。
- 手写格式与生成格式不得混用同一文件；能生成的一律生成。

判据：`<格式化命令> --check` 退出码 0；手工改掉一个空格后退出码非 0。

## 5. 资源离线可加载

- 关键路径不依赖运行时外网：字体、图标、样式库、脚本库、影像资源全部本地。
- 第三方库放本地固定目录，登记版本与来源；不引 CDN 直链。
- 离线或断网打开关键页面必须可用；联网能力作为可选增强，缺网时给明确提示。
- 外部资源引入前确认许可允许再分发。

判据：断网刷新关键页面，控制台无失败请求，核心功能可用。

## 6. 生成物可复现

- 生成物必须能从「权威源 + 脚本」重跑得到；生成命令写进文档与校验脚本。
- 输入固定：排序、编码、换行、数字精度都确定；顺序敏感处显式排序，不依赖目录遍历顺序。
- 生成物里不写生成时间、随机 id、绝对路径、机器相关字段。
- 生成物重跑无 diff 才算可复现；有 diff 说明脚本或输入不稳定。

判据：`<生成命令> && git diff --exit-code <生成物>` 无输出。

## 7. 资源体积与来源登记

- 单文件与单目录设体积上限；超限先压缩、裁剪或懒加载，再提交。
- 图片按展示尺寸导出，不直接放原始大图；同图多尺寸用统一命名规则。
- 大文件（影像、字体、数据包）放仓库外时，写清获取方式与校验值。
- 每个新增资源登记四项：来源、许可、生成/下载命令、用途。没有登记的资源不进库。
- 提交前确认资源确实被引用；被数据引用的资源必须一起提交，漏提交会在别人机器上 404。
- 运行时不下载资源；加载失败要有可见降级，不是静默空白。

判据：`git status` 里每个新增资源都能在数据或代码里搜到引用，且体积在预算内。

## 8. 数据与资源变更清单

改字段或加资源时按顺序确认：

1. 权威数据与示例；
2. 写入路径（表单 / 接口 / 导入脚本）；
3. 校验（前端 + 服务端）；
4. 读取层缺省处理；
5. 展示与空态、错误态；
6. 格式化与 `--check`；
7. 生成物重跑；
8. 文档中的格式说明；
9. 旧数据迁移与默认值；
10. 保存后重新读取验证。

漏任何一环的典型症状：能填不能显示、前端能存服务端拒收、生成物与源不一致、旧数据渲染出空白。

## 9. 验证模板

按项目替换 `<格式化命令>`、`<生成命令>`、`<生成物>`、`<数据校验命令>`。

```bash
# 格式化检查：只报告，退出码 0 才通过
<格式化命令> --check

# 生成物可复现：重跑后无 diff
<生成命令> && git diff --exit-code <生成物>

# 数据自检：结构合法、成对字段齐全、空值未变 0
<数据校验命令>
```

## 10. 自查

- [ ] 新字段四环齐全，能逐环指到代码位置
- [ ] 空值与 `0` 已区分，并用构造数据验证过
- [ ] 成对字段只有一半时被校验拒绝
- [ ] 唯一格式化器 `--check` 通过且幂等
- [ ] 重跑生成物无 diff
- [ ] 断网可用，控制台无失败请求
- [ ] 新增资源已登记来源、许可、体积、用途，且确实被引用

服务端写入与上传校验见 `./local-server.md`；模块与文件边界见 `./module-layout.md`。
