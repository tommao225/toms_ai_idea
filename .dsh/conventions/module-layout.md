# 目录、模块与文件边界

## 1. 层 → 该放什么 / 不该放什么

| 层 | 该放什么 | 不该放什么 |
|---|---|---|
| 通用层 | 无业务倾向的工具、通用组件、唯一的数据加载入口 | 业务字段、页面布局、业务规则 |
| 领域层 | 纯函数：校验、归一化、排序、筛选、统计、派生 | DOM 操作、网络、文件读写、第三方渲染对象 |
| 适配层 | 第三方库封装、请求、文件读写、格式转换 | 业务规则、页面编排 |
| 页面层 | 页面入口、交互状态、渲染、表单、页面私有逻辑 | 第二份业务计算、跨页面复用逻辑 |
| 服务层 | HTTP 入口、鉴权、入参校验、原子写入、落盘 | 页面渲染、前端交互 |
| 离线脚本 | 数据生成、格式化、迁移、批量修复 | 被运行时 import、依赖页面 |
| 数据文件 | 事实源数据，一处一份 | 前端逻辑、测试夹具、临时产物 |
| 静态资源 | 可复现生成的产物、第三方依赖副本、图片 | 手工改动的生成结果、密码与凭据 |
| 文档 | 约定、清单、说明、审计记录 | 参与运行时 |

新增文件先判断「属于哪一层」，再决定目录；不要因为「都叫工具」就塞进同一个文件。目录名可以按项目调整，层与依赖关系不能。

## 2. 文件边界

- 一个文件一个关注点：文件名要能回答「它负责什么」。
- 新文件目标 ≤ 300 行；已有文件只许变小，不许因为新功能继续膨胀。
- 超限时按职责拆：
  - 数据处理与纯函数 → 领域层
  - 交互状态与用户操作绑定 → 页面层
  - 可复用 UI → 通用层
  - 样式 → 对应的样式文件
- 不建「大杂烩工具」文件；同一文件里的函数应能被一句话概括。
- 不建 barrel 索引文件重导出全部模块；调用方直接引用目标文件，依赖关系才看得见。

## 3. 导出与命名

- 用具名导出，不用默认导出，除非项目既有风格统一使用默认导出。
- 只导出调用方真正需要的；内部函数不加导出标记。
- 命名：
  - 文件 `kebab-case`
  - 函数/变量 `camelCase`
  - 常量 `UPPER_SNAKE_CASE`
  - 布尔量以 `is/has/can` 开头
  - 数据字段沿用数据文件既有写法，不另造同义词
- 同一个概念全仓只用一个词：不要同时出现 `from/to` 与 `origin/destination` 这类平行命名。改名时连数据字段、渲染文本、测试一起改，不留半套。

## 4. 模块内部顺序

1. import
2. 常量/配置
3. 公开入口函数
4. 私有工具
5. 副作用初始化（尽量没有；有则放文件末尾，并写清为什么必须在此处执行）

函数内部：先校验参数 → 正常路径 → 边界与异常 → 返回。不要先铺一堆 helper 再找入口。

## 5. 状态

- 优先用参数与返回值传递状态。
- 页面级状态集中在页面入口的单一状态对象；不要散落成模块级可变变量。
- 模块级状态只允许「进程内单例资源」：缓存、弹层实例、注册表。每个单例必须只有一个设置入口和一个销毁入口。
- 清理要成对写：打开弹层时锁滚动，关闭时恢复；挂到页面外的菜单，关闭时移除；持有的节点引用，销毁时清空。
- 持久化字段新增时必须：给默认值、读取时归一化、兼容旧数据缺失、刷新后能恢复，并有对应验证。

## 6. 临时文件

- 临时验证脚本与输出放系统临时目录，或工作区内已忽略的临时目录；不要散落在源码目录、数据目录、文档目录。
- 一次性脚本用完删除；调试输出、测试数据不提交。
- 不用修改事实源数据文件的方式做测试；测试数据用内存对象或副本，结束恢复。
- 生成产物如果必须入库，先确认能从源可复现，并让校验命令能发现漂移。

## 7. 拆分示例

当一个文件同时做以下两件事，就该拆：

| 现状 | 拆法 |
|---|---|
| 一个文件同时管列表渲染、行内校验、弹层编辑 | 列表 / 校验 / 弹层三个文件，按职责分 |
| 一个文件同时管条目渲染、分组、筛选、滚动 | 条目 / 筛选 / 编排三个文件 |
| 一个文件同时管索引查询、状态机、两种选择器 | 索引 / 状态机 / 选择器分别成文件 |
| 一个样式文件同时管框架、表单、弹层 | 按组件拆成多个样式文件 |
| 一个脚本同时管数据抓取、转换、写入 | 抓取 / 转换 / 写入三步拆开，中间产物可检查 |

拆分前提：有明确职责边界；拆完调用方签名尽量不变；先纯搬移，再改行为。

## 8. 评审问题

1. 这个文件只做一件事吗？
2. 它所在目录与它承担的层一致吗？依赖方向对吗？
3. 导出是否最小？
4. 是否存在第二份同类实现或平行命名？
5. 临时文件、测试数据、调试输出清了吗？
6. 文件是否因为这次改动又变长了？
7. 新增的持久化字段有默认值与旧数据兼容吗？

分层与依赖的判定见 [layered-architecture](./layered-architecture.md)，改完的验证范围见 [verification](./verification.md)。
