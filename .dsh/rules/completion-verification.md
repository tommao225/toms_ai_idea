# 完成验证：代码存在 ≠ 已接线 ≠ 用户可见

## 1. 完成的四层

| 层 | 含义 | 怎么验 |
|---|---|---|
| 1 代码存在 | 文件/函数/字段写出来了 | 文件存在；全量语法检查通过 |
| 2 被调用 | 有真实引用与调用，不是死代码 | 全仓搜调用点；入口按钮/路由确实触发 |
| 3 被消费 | 结果被下游读取，影响页面/接口/文件 | 界面里看到元素/行为；接口返回或写入文件 |
| 4 持久化/可见 | 刷新后仍在、保存后数据正确、用户能看到 | 刷新页面；重新读取数据文件或存储；重启服务后再读 |

只做到第 1 层就报完成，属于虚假完成。

## 2. 完成证据按改动面

| 改动面 | 最低证据 |
|---|---|
| 脚本模块 | 全量语法检查通过 + 页面加载无报错 + 目标元素/行为出现 |
| 样式/结构 | 浏览器实际渲染截图或 DOM 状态；空状态与窄屏至少看一眼 |
| 共享组件 | 所有使用方逐一触发：能打开/选择/回调，行为与改动前一致 |
| 后台表单 | 打开表单面板、填写、保存、刷新后值还在；成功态、错误态、空输入各跑一遍；取消未保存内容会回滚 |
| 数据字段 | 后台能读能写、服务端校验接受、展示页消费、`<数据文件>` 落盘 |
| 服务端接口 | 正常请求 200 且内容正确；无 token / 坏 Origin / 坏 Content-Type 被拒 |
| 上传 | 合法文件落盘且路径可访问；伪造扩展名 / 超大 / 未知类型被拒 |
| 图形与动效 | 元素数量、关键属性与状态实际出现；数据来源与显示一致 |
| 存储结构 | 改输入、刷新、确认状态恢复；旧数据不白屏 |
| 删除/重构 | 全仓搜索旧名 0 命中；相关页面仍正常 |
| 文档 | README 的路径/按钮/字段与实际一致 |

## 3. 三种虚假完成

1. **算了就扔**：函数算出结果，但返回值被丢弃、没写文件、没更新界面。例：调用排序函数却不接收返回值，持久化顺序没变。
2. **死代码**：函数/组件写好了，但没有任何调用点。例：旧统计函数、旧浮层组件。
3. **占位/no-op**：校验函数存在，但关键分支空实现或恒真。例：只判断数值是否有限，却让空字符串通过。

## 4. 声明「完成」前检查

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 静态检查 | 全量语法检查通过；有单测的项目单测 0 失败 |
| 2 | 调用 | 至少一个真实入口触发 |
| 3 | 消费 | 页面/接口/文件能看到结果 |
| 4 | 持久化 | 刷新/重读/重启后仍正确 |
| 5 | 回归 | 相关页面与后台流程未被破坏 |
| 6 | 删除 | 旧实现/旧 class/旧 export 已清理 |
| 7 | 文档 | README/注释/规则同步 |

1-4 全过才可标「已验证」；只过 1-2 标「半集成」；只有 1 标「未集成」。

## 5. 确定性声明要带证据

涉及数据格式、生成产物、可复现结果时，声称「格式稳定」「重跑无 diff」「可复现」必须给出：

1. 固定命令（含工作目录/环境）
2. 实际输出（diff 为空、行数、哈希、测试 pass/fail 数）
3. 可重复执行的最小步骤

只写「我验证过」不算。命令模板如下，按项目替换 `<源码目录>`、`<生成命令>`、`<生成产物>`：

```bash
# 语法检查
for f in $(find <源码目录> -name '*.js'); do node --check "$f"; done

# 生成物可复现
<生成命令> && git diff --exit-code <生成产物>
```

各类证据的最小粒度：

- 单测：给出 pass/fail 数字
- 页面：给出视口、截图、读到的元素文本或数量
- 持久化：给出刷新前后的字段值
- 删除：给出全仓搜索命令与 0 命中结果

## 6. 验证范围按改动面收敛

- 单文件/单页：只跑相关检查 + 该页冒烟。
- 跨模块/共享函数：跑所有直接消费方的页面。
- 数据结构/服务端/校验：必须跑后台保存 + 重新读取 + 展示页消费。
- 安全/静态白名单：必须实际请求敏感路径、无 token 请求、坏 Origin 请求。
- 文档/规则：检查链接与命令可执行，不跑业务全量。

完整映射见 `../conventions/verification.md`；数据侧约定见 `../conventions/data-and-assets.md`，服务端约定见 `../conventions/local-server.md`。

## 7. 残留项必须标注

- 未完成：写清原因、影响、下一步。
- 半集成：写清缺哪层（调用/消费/持久化）。
- 已知风险：写清触发条件与验证边界。
- 不要用「基本完成」「应该没问题」替代状态标记。
