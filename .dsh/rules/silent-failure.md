# 静默失败：不报错 ≠ 正确

静默失败是「程序不报错、流程照走，但结果已经错了」。审查兜底、空值、过滤、配置时优先查它。

## 1. 典型形态

### 1.1 空值被当成合法值

- `Number("") === 0`：空字符串通过有限性检查，被当成合法数值参与计算。
- 空字符串当成「已填写」：成对字段的判空函数曾对两个空串返回 true。
- 空态缺失：没有输入时字段仍参与计算，得到 0 或 NaN，界面显示占位符却没有提示。
- 处理：空值显式判断；`""`、`null`、缺失分别处理；成对字段要么都有、要么都没有。

### 1.2 过滤条件把数据悄悄丢掉

- 渲染只返回同时具备某一对字段的子记录；保存路径却允许存空白值 → 保存成功但记录从界面消失。
- 处理：渲染与增强分开过滤；渲染保留所有合法记录，额外效果只对有完整字段的记录生效。

### 1.3 吞异常与假成功

- 加载请求 `.catch(() => null)`，把失败变成「没有数据」，界面看起来正常。
- 可选增强失败后静默退化为近似结果，没有任何提示。
- 写入存储失败被静默降级，刷新后数据丢失但界面不报。
- 显示层改了却没回写数据源：自定义下拉只改标签，没同步底层控件的值，业务读到旧值。
- 处理：能恢复的降级写日志/状态提示；不能恢复的显式报错；只吞可恢复的异常类型。

### 1.4 配置/字段写了但没人消费

- 某字段没有任何读取方；某配置只读不可编辑。
- 同一统计/筛选/排序出现第二份实现，页面数字对不上。
- 样式 token 被行内样式或旧规则覆盖，颜色看似改了实际没生效。
- 测试只断言函数存在，没有验证渲染与持久化，失败被当成通过。
- 处理：新字段必须同时有「写入 → 校验 → 读取 → 展示」消费链；没有消费方就不要写进数据。

### 1.5 运行态不是最新代码

- 服务进程在旧代码上启动，保存仍按旧格式写文件；代码已改，用户看到的是旧行为。
- 处理：改完后端必须重启，并用真实请求验证输出；不要只检查源码。

### 1.6 重构只清一半

- 结构里删了旧编辑区，样式里对应规则还在；页面不再用的 id/class 留在模板里，看起来像「还有功能」。
- 处理：删除后全仓搜旧名；结构、样式、脚本、文档同批清理。

## 2. 审查清单

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 空值 | `""`、`null`、缺失都有显式分支；空态不参与计算，不落进 0/NaN |
| 2 | 过滤 | 过滤条件不会让「已保存的数据」从页面消失而无提示；渲染与增强分开过滤 |
| 3 | 异常 | catch 分支有日志/状态/显式降级，不裸吞；只吞可恢复的异常类型 |
| 4 | 消费与同步 | 新字段/配置有真实读取点；显示层改动回写数据源；持久化失败有提示 |
| 5 | 派生 | 同一统计/筛选/排序/格式化只有一份实现 |
| 6 | 运行态与样式 | 服务重启后用真实请求验证；改主题后无行内/旧规则覆盖 token |
| 7 | 删除 | 旧实现无残留 class/id/export/import |
| 8 | 保存与测试 | 校验失败不会留下半份数据；测试断言覆盖渲染/持久化，不只查函数存在 |

任一不过，标注「⚠️ 静默失败风险」并定位断点。

## 3. 通用排查顺序

1. 先复现：记录输入、操作、预期、实际。
2. 确认数据：打印/读取状态对象、底层控件的值、存储内容。
3. 确认调用：入口是否真的绑定？函数是否被调用？返回值是否被消费？
4. 确认渲染：DOM 是否更新？元素是否可见？计算后的样式是什么？
5. 确认持久化：刷新后值是否还在？旧数据能否迁移？
6. 最后才改代码：先定位层级，再改那一层；不要用加延时、加空兜底掩盖。

定位不到层级就先加可观测性（日志/断点/临时断言），不要靠猜改代码。

## 4. 反模式

- 空 catch：`catch (e) {}`。
- `if (!value) return;` 把 `0`、空串、缺失混为一谈。
- 只改样式变量，却留下覆盖它的行内/硬编码值。
- 只跑语法检查就宣称页面正常。
- 用截图代替交互验证：页面打开正常不代表按钮能点、刷新不丢。
- 用加延时/加兜底掩盖时序与竞态。
