# 跨项目通用坑位

> 只收去掉具体项目名词后仍成立的条目。每条固定三段：现象（抽象）、根因、防法。数据相关另见 `../conventions/data-and-assets.md`，完成判定见 `../rules/completion-verification.md`。

## 1. 提交漏掉未跟踪文件

- **现象（抽象）**：提交只包含已跟踪文件的修改，新模块、资源、配置没进版本库；换机器或重新拉取后功能直接断。
- **根因**：只看了已跟踪文件的差异，没看未跟踪清单。
- **防法**：提交前检查未跟踪项并逐个确认；新增模块、资源、配置与代码同批提交；提交后用干净检出跑一次启动或冒烟。

## 2. 运行态仍是旧代码

- **现象（抽象）**：代码已改，实际行为仍是旧逻辑；据此得出的「改动无效」结论全是误判。
- **根因**：常驻进程、构建产物或缓存仍是上一版，改动没有触发重载。
- **防法**：改完服务端或构建产物必须重启或重新构建；用真实请求或真实交互验证，不只看源码；验证前先确认运行版本与工作区一致。

## 3. 空值被当成合法值

- **现象（抽象）**：缺失或空字符串被转换成有效数值或有效取值，界面出现「合法但错误」的默认值，甚至把整页数据带偏。
- **根因**：类型转换把空值折叠成默认值，判空只判类型不判内容。
- **防法**：空串、null、缺失分别显式判断；零、空、未设置是三种语义，不要合并；前后端校验规则一致。

## 4. 半保存与草稿泄漏

- **现象（抽象）**：多条写入只成功一部分，或取消编辑后仍留下空记录、空草稿；用户看到「保存成功」但数据不完整。
- **根因**：保存顺序、事务边界、草稿生命周期没有设计；失败路径没有回滚。
- **防法**：保存前统一校验全部目标；一次操作要么全写要么全不写；草稿在取消或关闭时回滚；失败时清理已写入的部分。

## 5. 派生逻辑多份实现

- **现象（抽象）**：同一口径在多个位置各算一遍，数字对不上；后加的入口口径与旧入口不同。
- **根因**：功能先在单个位置落地，扩展时复制而非抽取；没有单一事实源。
- **防法**：写之前先搜同类实现；出现第二次就抽到通用层或领域层；所有调用点同批替换，并从共享定义取值。

## 6. 统一组件替换破坏旧数据

- **现象（抽象）**：换成受约束的统一组件后，存量数据里的合法取值不再可选或显示为空白；字段变更后派生的展示字段残留旧值。
- **根因**：只按新数据设计取值域，没盘点存量数据；字段变更没同步清理派生字段。
- **防法**：替换前先导出存量取值分布并逐个确认可映射；保留手动输入或迁移通道；字段变更同批清理派生值并做回填校验。

## 7. 重构只清一半

- **现象（抽象）**：逻辑已删，样式、选择器、常量、文档里的旧名还在；后续读代码的人以为旧能力仍在。
- **根因**：只加新代码，没有同批删旧；没有全仓搜索。
- **防法**：删除后全仓搜索旧名（代码、样式、标记、脚本、文档）；同批提交；用搜索结果作为清理完成的证据。

## 8. 删 id/class 会打断自己的冒烟测试

- **现象（抽象）**：为清理死代码删掉某个标记属性，自己的自动化冒烟按该属性取不到元素，误判为页面损坏。
- **根因**：选择器同时承担「样式钩子」与「测试定位」两种职责，删除前没查消费方。
- **防法**：删除前搜索代码与测试；测试改用语义化或无障碍选择器而不是样式类名；删除后重跑冒烟并把结果作为证据。

## 9. 子 agent 结论不是事实

- **现象（抽象）**：并行报告互相重合也互相矛盾，部分结论基于旧运行态或未验证的推断；直接当修复清单会改错地方。
- **根因**：子 agent 只看到自己读到的片段；报告没有强制区分事实与推断；主 agent 未抽查。
- **防法**：主 agent 抽查可实测断言（计数、搜索、真实请求）；冲突以可复现实测为准；报告标注「确认 / 推断 / 未验证」；修复顺序由主 agent 按依赖重排。

## 10. 验证必须落到用户可见层

- **现象（抽象）**：语法通过、函数存在、接口返回成功，但用户实际操作仍失败或看不到结果。
- **根因**：验证停在构建、语法或单元层，没有覆盖真实交互与持久化往返。
- **防法**：至少验证一次用户路径：操作 → 保存 → 刷新 → 仍正确；覆盖空态与错误态；汇报写清验证到的层级与未覆盖范围。
