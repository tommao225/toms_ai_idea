# 电影专题

一个给「懂电影的人」看的电影导航站：按**不同口径的影史榜单**组织影片，带打卡。每个榜单上限 100 部，不够就是不够。

不是电影数据库，也不是推荐算法——是一本可以打卡的**放映刊物**。每个榜单都必须说清"凭什么这么排"，选片有立场，手记有观点。

## 边界

- 只收**榜单上的电影**，每榜上限 100 部，去重后约 800–3000 部，不做全量影库。
- **宁缺毋滥**：某类型整不出 100 部够格的作品，就只收 60 部、40 部，页面如实显示实际数量。绝不为凑整放进平庸之作——那会毁掉整站的立场。
- 无后端：数据在构建期生成成静态 JSON，运行时零请求；打卡存本机。
- 首期只做三个类型：悬疑 / 科幻 / 动作。
- 不展示"主演、简介、关键词"这类数据库字段作为主信息；它们折叠在详情页末尾。

## 目录

| 路径 | 内容 |
|---|---|
| `docs/` | 技术文档：实现路径、数据与口径、氛围规范、路线图 |
| `data/curated/` | 人工策展源文件：榜单目录 `lists/<list_id>/`、电影文本 `movies/<movie_id>/` |
| `data/media/` | 海报、剧照、板块头图；图片不进版本库，`credits.json` 记录来源 |
| `data/raw/` | 抓取缓存：TMDb 原始响应 |
| `data/movies/` | 构建产物：电影主档（去重后，JSONL） |
| `data/lists/` | 构建产物：每个榜单一个 JSON |
| `data/awards/` | 构建产物：奖项与获奖记录 |
| `pipeline/` | 数据管线：抓取、合并、取色、构建 |
| `web/` | 静态站：单页、无构建、无框架 |
| `tests/` | 计划：管线与站点的自动化检查 |

## 本仓库通用规则同样生效

根 `AGENTS.md` 与 `.dsh/` 的纪律对本专题同样适用：单一事实源、依赖单向、原子化、完成四层验证。唯一的例外是**数据文件允许长**（一个榜单一个文件，按行 diff），不要为了行数预算拆 JSON。

## 文档约定

- 文档里出现的路径**一律相对 `films/` 根**，不相对文档所在目录。
- 带 `*`、`{}`、`<...>` 或标注 `Mx` 的路径是**计划产物**，尚未存在。
- `data/curated/` 下的 TOML 已建空壳（含 schema 与待定占位），是 M0 的人工输入口。
