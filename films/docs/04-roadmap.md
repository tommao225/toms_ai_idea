# 路线图

原则：先打通**一条完整的垂直线**（一个类型 × 一个口径 × 一个榜单 × 全站呈现 × 打卡），再横向复制。榜单条数如实，不凑 100。任何阶段都不要并行铺宽度。

## 前置决策（挡住 M1）

**三个类型的「最伟大」榜单怎么定？**

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| A 引用权威榜 | 直接取 Sight & Sound / TSPDT / AFI 榜单并集 | 选片工作量最小 | 选片不由你，"这站有什么独特观点"说不出来 |
| B 自算 | 评分 + 奖项 + 榜单名次加权 | 完全可控 | 权重会被质疑，且要解释算法 |
| C 混合（推荐） | 权威榜做骨架，替换 15–25 部，每部写 `why_included` | 中等 | 需要你真正看过并敢表态 |

选 C 的话，M0 的产出就是三份"骨架 + 替换清单"，替换理由直接进榜单数据。

## M0 口径与策展（3–5 人日）

**交付**

- `data/curated/lists.toml`：先 3 个榜单（悬疑/科幻/动作 的最伟大）的口径卡
- `data/curated/entries/*.csv`：每榜最多 100 部，能凑到多少收多少，含 `movie_key`、`note`（一句手记）
- `data/curated/awards.toml`：A/A−/B/C 奖项 slug 表与类型映射
- `data/curated/genre-map.toml`：TMDb 类型 → 本站三类型的映射

**验收**

- 每榜 `count` 与条目数一致且 ≤ 100；rank 连续；每部有手记
- 人工抽 10 条判断"是否有凑数感"，有则删到不凑数为止
- 每榜口径卡的 `sources` 至少两个且带访问日期
- 手记里不出现剧情简介式句子（人工抽查 20 条）

## M1 数据管线（4–6 人日）

**交付**

- `pipeline/fetch.py`：按 `movie_key` 抓 TMDb，原始响应缓存到 `data/raw/`
- `pipeline/merge.py`：归一化、去重、`missing` 标注
- `pipeline/colorize.py`：海报转 webp + 取主色 + LQIP
- `pipeline/build.py`：产出 `movies.jsonl`、`lists/*.json`、`web/data/*`

**验收**

- 重跑两次 `build.py`，`git diff --exit-code` 通过
- 抽查 10 部：字段与 TMDb 页面一致；缺字段进 `missing`，不出现 0 或空串冒充
- 抓取失败有清单并非零退出

## M2 站点骨架（3–4 人日）

**交付**

- `web/index.html` + hash 路由四视图（榜单索引 / 放映单 / 详情 / 我的观影册）
- `assets/js/{app,list,detail,watch}.js`，`list.js` 分批渲染
- 无 JS 时列表仍可读（静态兜底）

**验收**

- 满 100 行渲染 ≤ 1200 DOM 节点；首屏 HTML+CSS+数据 ≤ 150KB
- 1000px 与 500px 两个视口无横向溢出
- 键盘可遍历整张放映单

## M3 氛围层（4–6 人日）

**交付**

- `tokens.css` 落地 `03-atmosphere-spec.md` 全部 token
- 列表行、卷标、首页开场、详情页六段、颗粒层、盖章动效
- 字体自托管子集化

**验收**

- 截图能让人问"这是什么站"
- 五种动效之外没有任何位移/缩放动画
- `prefers-reduced-motion` 下全部退化正确
- 对比度实测：正文 ≥ 7:1，次要 ≥ 4.5:1

## M4 打卡（2 人日）

**交付**

- `watch.js`：`mark/unmark/export/import`，localStorage 唯一写入口
- 我的观影册：已看数、按类型与年代分布、导入导出

**验收**

- 刷新不丢；导入按 `movie_id` 合并且不覆盖更新记录
- 清缓存前可导出；导出文件可再导入还原
- 打卡状态不只靠颜色区分（有戳记形状 + `aria-pressed`）

## M5 奖项维度（3–4 人日）

**交付**

- `data/awards/awards.jsonl`：首期录入 A 级 + 三类型 C 级
- 六个奖项榜单：`awards-all-tripod`、`awards-all-oscar`、`awards-scifi-hugo`、`awards-mystery-edgar`、`awards-action-stunt`、`awards-all-major`
- 详情页获奖记录段

**验收**

- 每条记录的 `award`/`category` 都在 `awards.toml` 里定义
- A 级获奖片与官方名单抽查 20 条一致
- 雨果奖条目类型复核（科幻/奇幻混奖，误收要标）

## M6 其余四个口径（5–8 人日）

按风险从低到高：

1. 评分最高（三源各一榜，不许合并）
2. 票房（名义 + 通胀调整两榜，票数只写"估算"）
3. 最长（剔除剧集与合集，超长实验片单列）
4. 最早（最后做：存世状态、短片、首映与发行之争都要标注）

**验收**

- 每榜口径卡写清 `known_bias`
- 「最早」榜每部有 `survival` 字段

## M7 地域扩展（5–8 人日）

**交付**

- 洲榜（亚/欧/美/非）与开放的国家榜（候选 ≥30 部才开放）
- 合拍片规则落地：`coproduction:true` 不进洲榜

**验收**

- 同一部片不出现在两个洲榜
- 样本不足的国家显示"样本不足"，不硬凑

## 总预算

约 29–43 人日（单人全职折算 6–9 周）。若只做"三类型 × 最伟大 × 打卡"的最小闭环（M0–M4），约 16–23 人日。

## 每阶段都要过的门

1. 数据质量门（`02` §9）全过，且**榜单没有为凑数添加的条目**
2. 站点在 1000px / 500px 两视口截图
3. 打卡与导出导入可用
4. 汇报写清"验证了什么、没验证什么"
